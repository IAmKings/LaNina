# Worker Platform Contract

## Scenario: Full-stack Worker foundation

### 1. Scope / Trigger

Read this scenario whenever a change touches the Worker entrypoint, HTTP envelopes, Cloudflare bindings, D1/R2 data flow, Cron scheduling or frontend/backend shared types.

### 2. Signatures

```ts
export function handleRequest(request: Request, env: Env): Response;
export function handleScheduled(
  controller: ScheduledController,
  env: Env,
): Promise<ScheduledHandlerOutcome>;

export interface Env {
  DB: D1Database;
  RAW: R2Bucket;
  APP_ENV: "local" | "staging" | "production";
  APP_VERSION: string;
  ENABLE_CRON: string;
  ENABLE_AUTO_PUBLICATION: string;
}
```

The Module Worker export is the only runtime entrypoint. The current implementation is `src/worker/index.ts`.

### 3. Contracts

- Public success: `{ data, meta: { generatedAt, dataCutoff, methodologyVersion } }`.
- Public failure: `{ error: { code, message, requestId } }`.
- Dates cross the HTTP boundary as UTC ISO-8601 strings.
- `/api/v1/healthz` returns only status, app version and environment.
- `DB` and `RAW` names are stable binding names in every environment; their resource IDs/names differ.
- `ENABLE_CRON` is a string and must equal exactly `"true"` before mutating scheduled work is allowed.
- `ENABLE_AUTO_PUBLICATION` is an independent string flag for only the 23:00 UTC publication
  decision. It must equal exactly `"true"`; missing or any other value fails closed. Local, staging
  and production all default to `"false"` for the first-month manual-publication policy.
- The Module Worker `scheduled` entrypoint attaches the asynchronous handler promise to
  `ExecutionContext.waitUntil`; `handleScheduled` remains directly awaitable for contract tests.
- The 15-minute ingestion group selects every due retry plus scheduled sources with
  `cadence_minutes < 60`. The hourly group selects only scheduled sources with
  `cadence_minutes >= 60`, so the two triggers cannot run the same normal source.
- The 22:30 UTC evaluation trigger uses its scheduled instant as the strict observation cutoff,
  derives the next Asia/Shanghai brief date and addresses the six code-owned thesis seeds in stable
  order. Pending production seeds return an explicit blocked result without D1/R2 access or draft
  mutation; approved seeds use the D1 evaluation-input adapter and idempotent draft module. The
  adapter reconstructs source health from runs completed by the cutoff and chooses a previous thesis
  stage only from versions whose data cutoff and creation time are both strictly earlier, so a retry
  cannot consume its own first result or later state.
- The 23:00 UTC publication trigger validates its exact slot and derives the preceding 22:30
  evaluation cutoff before making a publication decision. When `ENABLE_AUTO_PUBLICATION` is not
  exactly `"true"`, it returns `AUTOMATIC_PUBLICATION_DISABLED` before D1/R2, candidate repository
  or publisher access. When enabled, it reads only candidates bound to the exact cutoff and reports
  missing, duplicate and non-published candidates. Even a complete published set currently returns
  `AUTOMATIC_PUBLICATION_LIFECYCLE_UNAVAILABLE`: the scheduled seam cannot safely build the
  deterministic copy/review inputs required by `DailyBriefModule.freezeAndPublish`, and publishing
  six thesis drafts first would permit partial exposure. Manual publication modules remain
  independent of this flag. Unknown Cron expressions still fail closed as no-ops.
- Manual daily-freeze gate reconstruction uses enabled source configuration plus only source runs
  completed by the requested cutoff; later collections cannot repair an earlier stale snapshot.
  The atomic publication claim repeats that cutoff-bounded derivation, and an in-place retry that
  crosses the cutoff fails closed because the historical state can no longer be reconstructed.
- R2 is private; public content is projected through the Worker after license checks.
- Every Worker-generated response is hardened through `withSecurityHeaders`; static SPA/assets bypass that
  request handler and instead receive equivalent declarations from `public/_headers`. Any change to the shared
  header policy must preserve both delivery paths and cover them in the response-security test.
- Static assets normally bypass the Worker. Their response headers are therefore owned by the
  built `public/_headers` rules, while every route returned by `handleRequest` must pass through
  `withSecurityHeaders`. A security-header change must update and test both paths; `_headers`
  cannot harden a response generated by the Worker.

### 4. Validation & Error Matrix

| Condition | Required result |
|---|---|
| Unknown API route | HTTP 404 with `NOT_FOUND` envelope |
| Unsupported method | Stable public error; never fall through to a static asset as success |
| Invalid external payload | Reject at the source adapter entry; do not create a verified domain value |
| Missing/invalid environment config | Fail startup/request safely; never print secrets |
| Cron disabled | Structured noop log; no D1/R2 mutation |
| Production thesis seed pending | Structured blocked evaluation; no D1/R2 access or draft mutation |
| Automatic publication disabled | Structured delayed decision; preserve existing public output |
| Automatic publication enabled but atomic command unavailable | Structured lifecycle-unavailable delay; never publish thesis versions piecemeal |
| Exact 06:30 evaluation candidate missing/duplicate | Structured delayed decision; do not guess another version |
| Unknown Cron expression | Structured unknown noop; no D1/R2 mutation |
| D1/R2 failure | Stable internal error category and request/run ID; no raw exception in public JSON |

### 5. Good/Base/Bad Cases

- Good: `GET /api/v1/healthz` returns the typed envelope and `cache-control: no-store`.
- Base: an unknown `/api/v1/*` path returns 404 and a request ID.
- Bad: returning `env`, D1 metadata, stack traces or R2 keys from a public route.

### 6. Tests Required

- Unit: health response status, envelope, headers and absence of binding names.
- Unit: unknown route error code and non-empty request ID.
- Integration: one Worker serves both the SPA and API.
- Integration: local scheduled route runs with `ENABLE_CRON=false` and logs noop.
- Unit: evaluation/publication Cron expressions dispatch only their owning job, preserve the
  22:30 cutoff across the Asia/Shanghai date boundary and reject job failures on `waitUntil`.
- Unit: every deployment config defaults automatic publication to `"false"`; missing/malformed
  values remain binding-free, while exact `"true"` enters candidate integrity checks.
- Contract: UTC timestamps survive backend/frontend serialization without local-time mutation.
- Unit: security headers are present on Worker-generated responses and equivalent static-asset
  rules remain in `public/_headers`.

### 7. Wrong vs Correct

#### Wrong

```ts
return Response.json({ env, error });
```

This leaks bindings, configuration and an unstable exception shape.

#### Correct

```ts
return Response.json({
  error: { code: "NOT_FOUND", message: "未找到该接口", requestId },
}, { status: 404 });
```

The stable public contract stays independent of internal failures.
